# Solar compiler benchmark, 2026-11-02

Solar compiled the contracts 9.95× faster than native solc under Forge. This measures `forge build --force --skip test --skip script --extra-output storageLayout`, not the normal package build. It excludes tests/scripts, Hardhat, TypeChain, TypeScript and artifact exports. Both compilers passed 1,480 tests with one existing skip; 312 contract artifacts had matching ABIs and compiler-reported storage layouts.

| Measurement                           | solc 0.8.33 | Solar 0.3.0 | solc / Solar |
| ------------------------------------- | ----------: | ----------: | -----------: |
| Forge clean artifacts, contracts only |     18.235s |      1.833s |        9.95× |
| Forge no-op cache hit                 |      0.893s |      1.022s |        0.87× |

Five alternating clean builds per compiler, plus five measured cache hits after an untimed warm-up. Wall time includes Forge, import resolution and artifact I/O. Dependencies and compiler binaries were already installed; OS file caches were warm. Clean-build ranges: solc: 16.124–28.062s; solar: 1.468–2.326s. This was a shared development machine, not a dedicated benchmark host.

Every measured cache-hit log says `No files changed, compilation skipped`. That row measures the surrounding Forge work, not compiler code generation. The five-sample ranges overlap: solc 0.836–1.255s; Solar 0.927–1.796s. The 129ms median difference does not establish a Solar compiler regression.

CI on an 8-vCPU Linux runner measured the same five-run comparison:

| Measurement                           | Native solc |    Solar | solc / Solar |
| ------------------------------------- | ----------: | -------: | -----------: |
| Forge clean artifacts, contracts only |     21.553s |   1.437s |       15.00× |
| Forge no-op cache hit                 |    0.65014s | 0.65004s |        1.00× |

The cache-hit medians differ by less than 0.1ms in CI. Both compilers passed 1,480 tests with one skip; all 312 ABI/storage comparisons passed. [CI run and complete artifacts](https://github.com/hyperlane-xyz/hyperlane-monorepo/actions/runs/41512213782), measured on `3a848060d4265ee5aff8ae23d3e0cb8ff74b6cca`.

The normal package pipeline has a different scope. On this Mac, Hardhat selected **solc-js/WASM**. One clean `pnpm -C solidity build` took **71.389s**; its unchanged repeat took **3.848s**. The cold run started without Hardhat artifacts/cache, `dist` or generated TypeChain; prerequisites and the compiler download were prepared before timing. It compiled 343 Solidity files, generated 950 typings, ran `tsc`, fixed 346 factories and exported the build artifact. The cached run skipped Solidity compilation and typing generation but still ran the remaining package stages.

Those package figures are baseline context, not a Solar package-build comparison. `build:solar` produces Forge artifacts; it does not replace the package's TypeChain/TypeScript/export pipeline. The 9.95× local and 15× CI ratios apply to native Forge compilation only.

## Reproduce

Use the [Solar setup](../README.md#solar-experimental), then:

```bash
nvm use
pnpm -C solidity benchmark:solar --runs 5 --output /tmp/hyperlane-solar-results
```

The runner writes every command's stdout/stderr and `results.json`. It compares ABIs and recursive storage shapes after removing compiler-local AST/type IDs, and exits nonzero on a failed test, a missing test, a changed test status, or an ABI/storage difference. The `Solidity Solar` workflow runs the same comparison and uploads the full output.

[Recorded samples and selected artifacts](solar-2026-11-02.json). Implementation: `e548eb7be8fdb3f28cb89c65d3f5ccc09c79e80a`; source base: `2cc950aa96387ec5eaf528eafb637bfa31c90edd` plus the working diff committed there. No production contract source changed.

- Host: Apple M3 Pro, 11 logical CPUs, 36 GiB RAM, macOS 27.0.1.
- Node: v26.12.1; Foundry: nightly `a577a1142515f5a96935a525935936a2281b4c75`.
- Solar: native release build from v0.3.0 source archive at `e7a91fc70f29dc8d0c236d56a2aa7706dc2555cf`, without PGO. The archive build reports `commit.unknown`; the source revision is recorded separately.
- Baseline: solc 0.8.33, legacy pipeline (`via_ir = false`), matching current repository settings. Solar's default compiler pool uses eight threads; solc is single-threaded per compilation job.
- Tests: `isolate = false`, fuzz seed `0`, 50 runs; existing Everclear, Tron and fork exclusions. Existing skipped test: `HypERC20CollateralScaledDownRoundingTest.testRemoteTransfer_withFee()`.

## What the article means for this repo

The [100× headline](https://www.paradigm.xyz/writing/solar-100-faster-solidity) compares against solc via-IR. Our baseline uses the faster legacy pipeline, so these numbers measure the actual migration rather than that headline. Solar's typed MIR and EVM IR can optimize both compile time and generated code; the smaller runtime bytecode here is consistent with that design. It does not establish equivalent behavior beyond the tests and compiler outputs checked above.

Two test-runner assumptions needed fixing. Newer Foundry defaults to transaction isolation, which cleared transient fee quotes between calls and caused nine shared failures; the same 72 affected tests passed on the pinned v1.5 runner. Explicit `isolate = false` preserves the existing behavior. Solar also reused `block.timestamp` across two `vm.warp` calls; `vm.getBlockTimestamp()` makes both advances observable without changing the rate-limit assertions.

This is a development integration. Solar v0.3 codegen is [experimental](https://github.com/paradigmxyz/solar/blob/v0.3.0/CHANGELOG.md). Hardhat exports, production bytecode, CREATE2 addresses, ZKsync and Tron keep their existing compiler paths. Fork tests, Hardhat tests and production deployment equivalence were not covered by this benchmark.
