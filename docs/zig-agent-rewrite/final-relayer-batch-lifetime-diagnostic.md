# Relayer batch lifetime crash diagnostic

The exact-new-binary V4 ReleaseSafe process proof **failed** at the four-message `maxBatchSize=4` stage. The relayer exited `-6` (SIGABRT), with a segmentation fault in `ArenaAllocator.alloc` → `ArrayHashMap.getOrPutContext` → `Service.submit`, reached through transaction reconciliation. This is an actual runtime Source failure, not a policy or harness assertion adjustment. **Zero full V4 proofs are accepted.**

The run started at 15:58:12 UTC and ended at 16:08:40 UTC on 2026-11-06. Its recorded inputs and artifacts were unchanged through the failed run.

No batch completion or crash-recovery substage passed afterward.

Root identified the lifetime defect in the frozen `e0b95ebf0189e3cc75c3ae1e48a2d9581006e8d0` implementation: `simulateBatch` creates temporary `OwnedJson rebuilt`, places its `payload_details` and `vm_specific_data` child values into the caller's record, then destroys the temporary arena before `submit` continues. The child values are shallow copies that retain the temporary allocation/allocator context. The correction is owned by Runtime; independent review and corrected-source verification were pending when this diagnostic was sealed. No correction is included or accepted by this archive.
