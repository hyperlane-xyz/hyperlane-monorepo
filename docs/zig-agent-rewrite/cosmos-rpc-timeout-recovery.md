# Cosmos RPC timeout recovery

Cosmos and CosmosNative RPC fallback now separates the physical endpoint timeout from the aggregate owner deadline. A first peer can accept a request, stall for the full configured20s, and fail while the healthy second peer still has time within the retained120s owner budget. These are functional recovery fixtures, not performance measurements.

Rust's generic `FallbackProvider` bounds each provider call to30s and advances after a timeout. Cosmos RPC constructs that fallback from every configured RPC URL. The previous native nonhedged Pool instead gave the first physical request the entire20s session budget. Its session expired before the second peer could start. Converting that completed session timeout into `UpstreamReadTimeout` did not restore the missing peer budget. The [original read-only Source audit](../../zig/bench/results/cosmos-rpc-timeout-recovery/initial-source-audit.md.gz) retains the exact paths and the separate direct Tron/Aleo finding.

## API and owner boundaries

[Pool fallback configuration](../../zig/src/evm/pool.zig) adds `attempt_timeout_ms: ?u32 = null`. A configured cap must be1–300000ms; each physical endpoint receives the smaller of that cap and the remaining aggregate session budget. This preserves ordered nonhedged fallback. A null cap retains the existing EVM/default behavior; method-error classification, request IDs and response ownership are unchanged.

[ReadReplay configuration](../../zig/src/net/read_replay.zig) adds `use_owner_timeout: bool = false`. Opt-in requires a fallback Pool with a nonnull physical cap. It submits the retained owner's remaining budget as the aggregate session limit. Callback resumes and committed read sections do not refresh the deadline. Aggregate expiry and owner-clamped boundary timeouts retain control status. This adds no production heap allocations or worker threads.

[Resources](../../zig/src/agents/chain_source.zig) enables the separate cap and replay budget only for Cosmos/CosmosNative. Borrowed Pools must match the protocol and physical cap. Direct calls use a bounded120s default session intersected with the actual `rpc_deadline_ns` and HTTP owner deadline when supplied, with cancel/halt/expiry checks before and after the call. The default120s session ceiling alone does not establish the caller's operation Clock; an explicit owner binding supplies that deadline. [Destination Factory](../../zig/src/agents/destination/factory.zig) scopes bind and restore the actual deadline. The separate [HTTP physical-timeout recovery](rpc-physical-timeout-recovery.md) covers direct Tron/Aleo/Starknet producers and receipt owners.

## Recorded functional checks

All tests ran on the shared macOS host with the existing native curl library and disposable loopback HTTP peers. No agent role, production endpoint, SDK rebuild, Rust/C build, image or benchmark ran. The two real20s stall cases use the actual `Resources.open` constructor and production Tendermint RPC client: direct Cosmos and cooperative CosmosNative. They retain exactly one physical request per peer, the same underlying request bytes/ID, and integer9007199254740993 without precision loss. The cooperative callback's changing caller IDs remain handled by the existing replay substitution.
