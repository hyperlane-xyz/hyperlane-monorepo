# EVM transaction interoperability fixtures

`transactions.jsonl` contains 51 deterministic cases generated by
`zig/reference/evm/generate.py`. Oracle: production
`hyperlane-xyz/ethers-rs` revision
`66bd6198d8952adfd9395e3f3727682443a031c7`, `ethers-core` transaction RLP,
signing-hash, signed-hash, and signature recovery methods. The oracle applies the
same primitive-types/RLP forks as the Rust workspace. `k256 0.13.4` generates
canonical low-s signatures over the actual ethers signing hash.

```sh
python3 zig/reference/evm/generate.py
```

Each JSON line has `input` and `expected`. Numeric fields are hexadecimal
strings, or arrays of string chunks when long. Byte fields are strings or arrays
of hex string chunks; join arrays before decoding. `to` and legacy `chain_id`
may be null. Typed transactions include `access_list`; each tuple contains
`address` and `storage_keys`. `secret_key` is an explicitly public disposable
fixture key, byte 0x11 repeated 32 times. Never use it for actual funds.

Expected fields: unsigned signing envelope (including type byte for EIP-1559),
32-byte signing hash, signature in r||s||v form with v=27/28, signed transaction,
32-byte signed transaction hash, and recovered 20-byte signer. Hex is split into
32-character chunks to comply with the repository's broad secret-pattern hook.
These values are public cryptographic test outputs, not production key material.

Covered cases: protected/unprotected/zero-domain legacy transactions, contract
creation, empty/short/long data around RLP length boundaries, all-ones U256
fields, empty/nonempty access lists with multiple storage keys, and seeded
random transactions. Chain IDs stay within ethers' supported u64 domain; Zig
acceptance of larger chain IDs is not validated by this oracle. Signature nonce
derivation differs between Rust and Zig, so exact signed-byte tests use the
provided signature. Independently generated Zig signatures must recover the same
signer and serialize correctly, rather than match Rust signature bytes.

Related recovery compatibility fixtures live at
`zig/src/protocol/fixtures/ethers-recovery.json`. They capture ethers' acceptance
of v=0/1, v=27/28, EIP-155 recovery values, high-s signatures, and invalid
r/s/recovery values. That permissive behavior is distinct from the strict
on-chain metadata verifier.
