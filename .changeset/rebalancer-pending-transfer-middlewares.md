'@hyperlane-xyz/rebalancer': minor

An optional `pendingTransferMiddlewares` list was added to the rebalancer config so that collateral is no longer reserved for user transfers that will never be delivered. Each entry wraps the Explorer client in order: the first entry filters the raw Explorer result and each later entry sees what is left. When ignored messages leave fewer transfers than requested, an entry re-queries the Explorer with at least double the limit until enough transfers are kept or the Explorer has no more, and throws once the limit would exceed 25,600 rows. A `relayerDenylist` entry loads the relayer runtime denylist from an `https://`, `http://` or `file://` URL without credentials at startup, failing startup if the file cannot be loaded or is invalid, and re-fetches it on the first Explorer query after each `refreshIntervalSecs` (default 60), keeping the last good rules on a failed refresh. Rules are matched like the relayer, including `match.bodyRegex`, which is tested against the lowercase hex message body with RE2 (the `re2js` dependency was added), in linear time like the relayer; a pattern RE2 rejects, or that RE2 and the relayer's regex engine would read differently, invalidates the file. Address rules with `matchBody: true` also match a 20-byte EVM address at any byte offset of the message body. A `blacklistIsm` entry ignores messages to EVM destinations listed by a BlacklistIsm that on its own makes the router ISM reject them; BlacklistIsms that only block together are treated as never blocking. It reads the router ISMs once at startup and keeps only those BlacklistIsms and their blacklisted ids: a router's custom ISM is derived in full, while the mailbox default ISM is read only along the branches the route's origins use. Startup fails if an ISM cannot be read or if no route pair has such a BlacklistIsm. It skips with a warning any route pair whose ISM always rejects because a domain routing ISM has no module for the origin, follows mailbox default ISM wrappers, and fallback routing ISMs without a module for the origin, to the default ISM of the mailbox they are bound to, treats a routing ISM in the mailbox default ISM that cannot be queried by origin as never blocking, treats amount routing ISMs as never blocking, and re-reads a route pair's BlacklistIsm ids only when one of its messages is queried and `refreshIntervalSecs` (default 600) has passed, reading each BlacklistIsm once per refresh and keeping the last known ids if a read fails. Transfers that are already tracked are dropped once a middleware ignores them. Without the field, no middlewares run. `PendingTransferMiddlewareType` and the `PendingTransferMiddlewareConfig` type were exported.
