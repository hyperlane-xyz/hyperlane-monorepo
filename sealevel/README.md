# Sealevel programs in Go (goSVM)

Go ports of the Rust Sealevel programs in `rust/sealevel`, compiled to SBF with
[goSVM](https://github.com/CrocSwap/goSVM). Experimental: goSVM is an unaudited
alpha. Port conventions: [PORTING.md](PORTING.md).

## Layout

```
sealevel/
  go.mod             one module for everything; replace gosvm => ./.gosvm/sdk
  .gosvm/sdk/        pinned goSVM SDK-2 snapshot (gosvm/solana, gosvm/sdk/...)
  libraries/<name>/  shared Go packages, named after rust/sealevel/libraries
  programs/<name>/   one package per program (raw Process entrypoint),
                     mirroring rust/sealevel/programs paths
  internal/          host-only test helpers and the library subset check
  testdata/          Rust-generated byte vectors (tools/rust-vectors)
  target/            build output (ignored)
```

Programs are plain Go packages with `func Process(c solana.Context) uint64`.
No `gosvm.json` or schema-2 codegen: Hyperlane's wire formats are Borsh, which
schema 2 can't express.

## Build and test

```sh
go test ./...                       # native Go tests (from sealevel/)
GOSVM=gosvm-int4 ./build-programs.sh # every program, fogo-v0 + solana-v3
```

`build-programs.sh` writes `target/<profile>/deploy/<rust lib name>.so`
(e.g. `hyperlane_sealevel_test_ism.so`), so the Rust functional suites can load
them through `SBF_OUT_DIR`. See PORTING.md for running those suites.

Golden tests read the shared Sealevel goldens in
`rust/sealevel/interface/testdata/golden` (`SEALEVEL_GOLDEN_DIR` overrides the
directory) and fail if a file is missing.

To regenerate `testdata/rust_vectors.json`:

```sh
cp ../rust/sealevel/Cargo.lock tools/rust-vectors/   # pins the SPL and IGP crates' deps
(cd tools/rust-vectors && cargo run -q) > testdata/rust_vectors.json
rm tools/rust-vectors/Cargo.lock
```

The tool has no lockfile of its own: a fresh resolution picks crates newer than
rustc 1.86 allows. Keep its default target dir. Sharing `rust/sealevel`'s
target dir clobbers the unhashed cdylib rlibs (`libaccount_utils.rlib`, ...)
and breaks that workspace's builds.

## goSVM pin

- CLI: [paulbalaji/goSVM `hyperlane-integration-4`](https://github.com/paulbalaji/goSVM/tree/hyperlane-integration-4)
  (3ddeff0): upstream `main` `939b215`, which merged our earlier PRs #9 to #24
  in [CrocSwap/goSVM#25](https://github.com/CrocSwap/goSVM/pull/25)
  (`GetReturnData`, `Secp256k1Recover`, `Keccak256`, the memmove fix,
  `MoveLamports`, `Log`/`Log64`/`LogPubkey`, `pda.Seeds.FindAddress`,
  `-max-accounts 64`, 64 CPI metas / 4 signer groups, bulk copies and zeroing
  on `sol_memmove_`/`sol_memset_`, System PDA-signed ops and the
  Token/Token-2022/ATA SDK helpers), plus the open draft PRs
  [#27](https://github.com/CrocSwap/goSVM/pull/27) (whole-word runtime loads,
  stores and key comparisons), [#28](https://github.com/CrocSwap/goSVM/pull/28)
  (`solana.FindAddress` on `sol_try_find_program_address`, also behind
  `pda.Seeds.FindAddress`), [#29](https://github.com/CrocSwap/goSVM/pull/29)
  (word-at-a-time `==` on byte arrays), [#30](https://github.com/CrocSwap/goSVM/pull/30)
  (exact `MinimumBalanceFor` fast path at thresholds 2.0 and 1.0) and
  [#31](https://github.com/CrocSwap/goSVM/pull/31) (word compares in
  front of hand-written byte compare loops). Install it with
  `git clone -b hyperlane-integration-4 https://github.com/paulbalaji/goSVM && bash goSVM/scripts/install.sh ~/.local/bin`,
  then point `GOSVM` at it. The build commands below call it `gosvm-int4`.
- SDK snapshot: `sdk_sha256` 6e97ac4bb6571bc2d44438fc0a1afe263f678034678e475356660f2301ca503f
  (copied from `gosvm-int4 new -schema 2 -sdk 2`).
- Backend: platform-tools v1.57 (`gosvm toolchain install`).

To update the pin, scaffold a project with the new CLI and copy its `.gosvm/`
over this one. `.gosvm/sdk` is goSVM source, Apache-2.0; its `LICENSE` and
`NOTICE` are copied alongside.

Benchmarks against the Rust programs: [benchmarks/2026-10-19](benchmarks/2026-10-19/README.md).
